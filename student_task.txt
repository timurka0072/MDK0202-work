Практическое задание: Анализ проекта из репозитория

Исходные данные
- Запустите проект локально

Что нужно сделать:
Часть 1:
1. Изучите `README.md` и структуру файлов.
2. Запустите приложение (или посмотрите скриншоты).
3. Ответьте письменно:
   - Какую проблему решает приложение?
   - Кто его целевая аудитория?
   - Назовите 3 основные функции.

Часть 2. Моделирование: Use Cases
1. Выделите 2–3 ключевых сценария использования (например: «Добавить задачу», «Авторизоваться»).
2. Для каждого сценария оформите Use Case.
3. Постройте простую диаграмму Use Case (можно от руки, в draw.io или Miro).

Часть 3. Проектирование тестов: Test Cases
1. Для одного из Use Case разработайте 5–7 тест-кейсов:
- 3 позитивных (ожидаемое поведение),
- 2–3 негативных (ошибки ввода, граничные значения),
2. Оформите в таблице:
| ID | Шаг | Ожидаемый результат | Фактический | Статус |
|----|-----|---------------------|-------------|--------|

Часть 4. Анализ рисков и предложений (15 мин)
1. Укажите 2–3 потенциальных риска для проекта (технических, пользовательских, бизнес-).
2. Предложите 1 улучшение интерфейса или логики с обоснованием.

Что сдать:
- Папка `/results` с файлами:
  - `use_cases.md` (или `.docx`)
  - `test_cases.xlsx` (или `.md`-таблица)
  - `risks_and_improvements.md`
  - `diagram.png`
